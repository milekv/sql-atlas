# Implementation status — 2026-11-27

The Polish content review, Oracle importer, benchmark scenario and rewrite safeguards were merged in [PR #18](https://github.com/milekv/sql-atlas/pull/18) at `5716b47`, building on `main` at `8e0da80`. GitHub Pages is live at <https://milekv.github.io/sql-atlas/>. The pre-merge incremental patch was verified on a clean copy; the public repository now contains those changes.

## Implemented in current source

- P0: source ranges, selected repeated findings, Monaco markers and click navigation, PL/EN web/CLI/Action/VS Code language support. A targeted CTE action scan now checks the main DELETE/UPDATE rather than WHERE inside the CTE; regression tests cover SQL Server and PostgreSQL cases.
- P1: bounded SQL Server Showplan XML parser, actual/estimated operator tree, per-thread counters, object/index, estimated/actual rows, executions, parallel flags, DOP and granted/used memory. Two real Microsoft SQL Server plans with 27 and 34 operators are tested in addition to synthetic edge cases. The UI has a navigable tree, operator detail panel and a second-plan structural comparison. The source samples have different `QueryHash`; the UI warns against interpreting the comparison as a speedup for the same query.
- P1: separate STATISTICS IO/TIME Messages importer with table reads and compile/execution timings. It intentionally does not correlate independently pasted messages to the imported plan.
- P1: Oracle DBMS_XPLAN text importer for one estimated or actual cursor plan, with operation navigation, per-operator metrics, predicates and notes. The parser was tested against Oracle 19c and 21c documentation examples (including a seven-operator cursor plan), UI interaction tests and bounded synthetic edge cases; it does not claim measured Oracle database execution.
- Index advisor: conservative PostgreSQL-only candidates. Literal/comment text, unknown aliases, ambiguous unqualified columns, derived CTE names and schema-qualified table names are excluded; OR alternatives are not combined into a composite index where the current DDL builder cannot identify the physical table reliably. It still lacks schema metadata and existing-index awareness; candidates are never applied automatically.
- Rewrite safety: the random-sort rule no longer suggests a sampling rewrite that changes semantics; PostgreSQL-specific index snippets are not presented for T-SQL and other dialects.
- Benchmark Lab: PostgreSQL server scripts and an actual embedded PGlite WASM run on 200,000 rows with `EXCEPT ALL` multiset equality (49,894 matches, zero differences), six JSON EXPLAIN ANALYZE measurements and recorded environment. A separate deterministic SQL Server setup and IO/TIME measurement scenario is prepared, but has not been executed here.
- Repository: English/Polish READMEs, architecture/plan/integration/benchmark/release/security documentation, third-party notice, SVG banner and 1280×640 Social Preview. Application screenshots were captured from local Chromium for earlier features. The public browser demo reflects the merged source; npm, VS Code Marketplace and the tagged GitHub Action have not been republished with the Oracle importer.
- The Monaco editor and its worker are bundled locally. A browser test exposed the earlier CDN dependency by leaving the editor at “Loading...” when network access was restricted; the corrected build loads Monaco without external requests.

## Verification and blockers

PR #18 passed 129 unit/component tests across 19 files, typecheck and the full web/CLI/Action/VS Code build in CI. The GitHub Action smoke test and GitHub Pages deployment passed on the merge commit. `npm pack --dry-run` (six files) and VSIX packaging (nine files, including English/Polish localization) succeeded locally. In the live Pages app, the Oracle sample loaded, operator navigation displayed the correct object/predicate/counters, PL/EN switching updated the view, and invalid text showed an error without stale results. This is a targeted browser smoke test, not exhaustive coverage. The local Chromium launcher is incomplete and Playwright download returned HTTP 403; there is no VS Code host executable here for an extension integration test. The PGlite run is embedded PostgreSQL WASM; no server PostgreSQL or SQL Server instance was available.

## Remaining work

P0 still needs comprehensive PL/EN page review and a dialect-aware parser for cases where regex/lexical masking is insufficient. P1 still needs more real plans across SQL Server versions, statement classes, adaptive operators and runtime warning variants; values are reported, not interpreted as causal diagnoses. Oracle DBMS_XPLAN needs more real plans and format variants. SQL Server benchmark measurements, a real VS Code screenshot, extension host smoke testing and release version alignment are incomplete. Do not label this source 1.0.
